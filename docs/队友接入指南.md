# 队友接入指南 — 拉取代码 + 调用大模型

> 面向项目组成员。目标：**拉到最新代码 → 跑起来 → 用上大模型**。
> 全程约 5 分钟。遇到问题直接看最后一节「常见问题」。

---

## 第 0 步：环境检查（1 分钟）

只需要一样东西：**Node.js ≥ 18**（项目零第三方依赖，**不需要 `npm install`**）。

```bash
node -v        # 应输出 v18.x 及以上，例如 v22.22.2
```

没有 Node？去 [nodejs.org](https://nodejs.org) 下载 LTS 版安装即可。
检查版本低于 18 会报错（项目用到了内置 `fetch` 与 `base64url`）。

---

## 第 1 步：拿到代码

### 方式 A：从团队仓库克隆（推荐，可持续同步）

```bash
git clone <团队仓库地址>
cd agent-bank
```

以后同步最新版：

```bash
git pull
```

> 如果提示需要账号密码：Gitee/GitHub 要用「个人访问令牌（Token）」而不是登录密码。
> 如果之前改过本地文件导致拉不下来：先 `git stash` 存起来，`git pull` 之后再 `git stash pop`。

### 方式 B：解压代码包（一次性）

拿到 `agent-bank-v2.zip` 后解压即可，目录结构应包含 `server.js`、`lib/`、`public/`、`docs/`。

> 代码包里**不含** `data/llm-config.json`（API Key 不入仓库），需要你按第 2 步自己补。

## 第 2 步：配置大模型（关键一步）

**不配置也能跑**——系统会自动降级为本地规则引擎，所有安全机制、所有功能都正常，只是听不懂口语化表达（比如"给我妈打两百块钱生活费"）。

### 先决定用哪个 Key（三选一）

| 方案 | 适合谁 | baseURL | 说明 |
|------|--------|---------|------|
| **① 自己的百炼 Key**（推荐） | 有阿里云账号的人 | 去百炼控制台复制你自己的接入点地址 | 互不干扰、互不消耗额度，新人免费额度足够开发测试 |
| **② 借用主账号 Key** | 临时测试 | `https://ws-uzihohqyfpp64ame.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | **必须是这个专有地址**，换成别的地址会报 401 |
| **③ 其他厂商** | 手上有别的 Key | 按厂商文档填 | DeepSeek / 通义 / Kimi / 智谱等 OpenAI 兼容协议都支持 |

**模型名**：填 `qwen-plus`（均衡，演示效果好）。想换 `qwen-max`（最强）或 `qwen-turbo`（最快）都可以。

> ⚠️ **最常踩的坑**：Key 和接入点地址必须**配套**。用别人的接入点配自己的 Key（或反过来）一定会 401。
> 百炼控制台 → 「模型服务」里能看到属于你自己账号的接入点地址。

### 写配置（两种方式选一种）

**方式一：配置文件**（本地开发推荐）

```bash
cp data/llm-config.example.json data/llm-config.json
```

然后编辑 `data/llm-config.json`：

```json
{
  "baseURL": "https://你的接入点地址/compatible-mode/v1",
  "apiKey": "sk-你的完整Key",
  "model": "qwen-plus"
}
```

**方式二：环境变量**（不想让密钥落盘时用）

```bash
# Linux / macOS / Git Bash
export LLM_API_KEY=sk-你的完整Key
export LLM_BASE_URL=https://你的接入点地址/compatible-mode/v1
export LLM_MODEL=qwen-plus
```

```powershell
# Windows PowerShell
$env:LLM_API_KEY="sk-你的完整Key"
$env:LLM_BASE_URL="https://你的接入点地址/compatible-mode/v1"
$env:LLM_MODEL="qwen-plus"
```

> 环境变量优先级高于配置文件。设置了 `LLM_API_KEY` 后，`llm-config.json` 会被忽略。

## 常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| 徽标显示「规则引擎模式」 | 没配置 / Key 写错 / 配置文件名写错 | 确认文件是 `data/llm-config.json`（不是 `.example.json`），重启服务 |
| 请求报 401 Invalid API-key | Key 不完整，或 Key 与 baseURL 不配套 | 完整复制 Key；用别人的接入点地址就必须配别人的 Key |
| 报 `EADDRINUSE` | 3000 端口被占用 | `PORT=3001 node server.js` |
| 大模型时好时坏 | 网络不通/超时（12 秒） | 会自动降级规则引擎，不影响演示；检查网络或代理 |
| 页面白屏 / 点登录没反应 | 浏览器缓存了旧版页面 | `Ctrl + F5` 强制刷新 |
| 启动后数据是空的、没有历史记录 | `data/db.json` 不入库，属正常 | 每个环境（含线上）数据独立，首次运行会生成种子数据 |
| 提示 `git pull` 有冲突 | 本地改过文件 | `git stash` → `git pull` → `git stash pop`，手工解决冲突后再提交 |
| 想重置演示数据 | — | 删掉 `data/db.json` 重启即可恢复初始状态 |

## 安全红线（请务必遵守）

1. **不要把自己的 API Key 提交进仓库**。`data/llm-config.json` 已在 `.gitignore` 中，别用 `git add -f` 强加。
2. **不要在群里直接发 Key**。请私发，或各自申请自己的 Key（更推荐）。
3. **不要 force push `main` 分支**（`git push -f`），会覆盖其他人的提交。
4. **大模型在本项目中只有"嘴"、没有"手"**：它只能把你说的话解析成结构化意图，任何资金操作都必须经过权限网关的用户双重验证。改代码时请勿破坏这条边界（详见 README「大模型接入的安全边界」）。
