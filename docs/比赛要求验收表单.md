## 0. 给 AI 的执行说明（每次收到本表单时按此流程跑）

### 第 1 步：环境准备

```bash
cd <项目目录>
node server.js &                      # 后台启动
sleep 3
curl -s --noproxy '*' -o /dev/null -w "%{http_code}" http://127.0.0.1:3000/   # 必须 200
```

> ⚠️ **注意**：本机有 HTTP 代理，`curl` 不加 `--noproxy '*'` 会拿到假的 502；
> 端口若被占用（`EADDRINUSE`）会静默跑旧代码，**必须确认端口是新起的进程**。

### 第 2 步：跑自动化核查脚本

```bash
BANK_BASE=http://127.0.0.1:3000 node tests/check_competition.js
```

脚本自动判定所有标 `A` 的项，输出带编号的 PASS / PARTIAL / FAIL + 证据，**直接对照填入下表**。

### 第 3 步：人工走查脚本无法判定的项（标 `M`）

按「验证方式」列逐条执行：调一次 API 看响应结构 / 打开页面走流程 / 用指定话术对话。

### 第 4 步：填写并出报告

- 每项填 `2`（达标）/ `1`（部分）/ `0`（未实现）
- 列出所有 `0` 分项，按优先级排序
- 与上一版对比，**不允许分数回退**
- 报告写到 `outputs/版本符合度报告_vX.Y.md`

### 判定口径

| 分 | 含义 | 判定标准 |
|---|---|---|
| **2** | 达标 | 功能完整、可演示、可复现，有证据 |
| **1** | 部分 | 能跑但有明显缺口 |
| **0** | 未实现 | 无此功能，或存在阻断性缺陷 |

**A/M 列**：`A` = 脚本自动 ｜ `M` = 人工走查 ｜ `A+M` = 脚本出初判、人工确认体验

### 本轮已修复（初版验收抓到的真实 Bug）

| # | 问题 | 严重度 | 说明 |
|---|---|---|---|
| 1 | **`confirm` 接口返回 `{}`** | 🔴 阻断 | 上一轮并发修复把 `confirmAndExecute` 改为 async，但 `server.js` 未 `await`，`JSON.stringify(Promise)` → `{}`。**所有转账确认都会失败** |
| 2 | 定时转账执行恒失败 | 🔴 高 | `doTransfer` 在 `type=scheduled` 时返回 Promise，`schedulerTickInner` 未 `await` → `r.ok` 恒 undefined |
| 3 | 调度器返回值丢失 | 🟡 中 | `/api/scheduler/tick` 未 `await`，`fired` 字段丢失 |
| 4 | setInterval 异常被吞 | 🟡 中 | 异步函数异常无法被 try/catch 捕获 |

> **教训**：这 4 个全是「同步函数改异步后调用方未同步更新」的连锁反应。
> 后续任何把函数改成 `async` 的改动，都必须全局搜索调用点确认已 `await`。
