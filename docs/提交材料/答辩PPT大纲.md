## P2 一句话说清我们解决什么

**大字**：智能体永远只是「申请人」，永远不是「执行人」。

三段式排版：
```
能理解 → 能规划 → 能组合工具 → 但每一个写操作
                                都必须回到用户本人的两道凭证
```

【讲稿】这句话是全场的锚。后面每一页都是在证明这句话不是口号，是代码结构。

## P3 行业普遍理解错了难点

| 常见认知 | 真实难点 |
|---|---|
| 模型不够聪明 | 模型会**理解错**（指代错人、同音字选错） |
| 多给点上下文就行 | 模型会**被骗**（账单商户名里藏指令） |
| 换个更大的模型 | 模型会**幻觉**（「上个月」解析成 2023-09） |

**结论**：不能假设模型是对的。模型输出只是「意图提议」。

【讲稿】这三行是我们踩出来的，不是推演出来的——每一条都有对应的线上缺陷记录。

## P4 三层解法（总纲页）

```
第一层  把权限做成结构   P0–P3 分级，高危动作智能体永久无权
第二层  把确认做成数学   HMAC 参数指纹，改一个字符就失效
第三层  把攻击做成回归   70 条攻击 + 25 条误伤对照，每次合并全绿
```

【讲稿】注意第三层的「25」。误伤和漏拦一样是事故——把用户正常问「你们风控规则是什么」也拦掉，产品就废了。

## P5 系统架构

一张分层图（照 `技术方案文档.md` §3 重绘）：

```
表现层 public/        ← 可自由重构，不承担安全责任
      ↓ 只走三个入口
网关层 gateway        ← 数据隔离 / 权限 / schema / 指纹 / 限速 / 审计链
      ↓
能力层 16 个模块      ← 资金 / 通讯录 / 订阅 / 挂失 / 记忆 / 计划 / 上下文
```

右下角标注：`零第三方依赖 · 6,200 行 · Node ≥ 18`

【讲稿】强调「表现层可自由重构」——这是刻意的：安全责任不在 UI 上，所以 UI 怎么改都不会破坏安全。这条纪律后来救了两次。

## P6 防线一：数据隔离（不是关键词过滤）

**左**：错误做法 —— 正则黑名单，打地鼠
**右**：我们的做法 —— 指令与数据两条通道，数据再像指令也进不了执行路径

底部数据条：`70 / 70 拦截　25 / 25 无误伤`

**配图**：一张拦截卡截图（带 `#A0903` 审计编号）

【讲稿】扩容语料时抓出一处误伤：裸「规则」二字就命中，把「说明一下你们的风控规则」误杀了。所以门禁要求拦截率和放行率**同时**达标。

---

## P7 防线二：P0–P3 权限分级

四象限或阶梯图：

| 级别 | 例子 | 智能体 |
|---|---|---|
| P0 只读 | 查余额、查账单 | 直接答 |
| P1 低敏写 | 定时转账、取消订阅 | 申请 + 一次确认 |
| P2 资金 | 转账、申购、挂失、锁资 | 申请 + **支付密码 + 短信** |
| P3 高危 | 解绑卡、改支付密码、解绑手机 | **永久无权** |

**高亮一句**：P3 不是「暂不支持」，是产品结论。

【讲稿】把解绑卡交给一条可能被注入的链路，等于把最高危权限外包给模型。这四类我们做的是「解释为什么必须你本人 + 深链 + 返回续接」，不是简单写「不支持」。

## P8 防线三：HMAC 参数指纹（最有说服力的一页）

**视觉**：左边授权单卡片，右边数学公式

```
fingerprint = HMAC-SHA256(金额 ‖ 收款人 ‖ 收款账户 ‖ 资源ID)
展示给用户：7F3A·9C21
```

**演示截图对照**：
- 正常确认 → ✅ 成功
- 改金额再确认 → ❌ 阻断「参数与指纹不匹配」，原单据仍为 ¥100

**一句话**：这不是靠提示词让模型别改，是**数学上改不了**。

【讲稿】提示词能约束模型，但拦不住中间人、拦不住前端 bug、拦不住用户手误。只有密码学能。

## P9 防线四：收款人解析层 —— 不猜

三态表格：

| 状态 | 规则 |
|---|---|
| verified | 可转；有同音联系人**必须提示** |
| pending | 单笔上限 **¥50** |
| unknown | **直接拒绝**，给两个按钮让用户自己选 |

**配图**：同音混淆卡截图（妈妈 → 张桂芳，提示还有「妈玛」李梅）

**底注**：解析不到就停下来问。「系统会猜」是攻击者最喜欢的东西。

【讲稿】这里有个细节：同音识别用同音表，**不用编辑距离**——编辑距离会把「小红」和「小李」误判成相似，反而制造误伤。

## P10 防线五：审计哈希链

```
每条：hash = HMAC(prev_hash ‖ payload)
任何一条被改 → 断点处立即检出
```

**配图**：安全驾驶舱的「审计链校验：连续完整（1,400+ 条）」

**讲一个真实故事**（这页的价值全在故事里）：
> 日志超 2000 条触发分级保留，裁剪后 id 跳号，链校验报「链接断裂」。
> 原注释写着「允许这种情况」，但**实现里没有这个逻辑**。
> 如果不压测到 2000 条，答辩现场点校验就会当场变红。
> 修复方式：裁剪后重封链 + 启动自检，留痕 `audit.reseal`，**不掩盖**。

【讲稿】这段一定要讲，它证明我们不是在演示一个顺利路径，而是真的在测自己的东西。

## P12 S3 订阅黑洞：识别规则必须够硬

**左**：三个真实订阅（云盘 ¥9 / 视频 ¥25 / 音乐 ¥15）
**右**：识别条件

```
同商户 + 金额误差 ±1% + 至少两段间隔落在同一周期
排除电商 / 外卖 / 商超
```

**踩坑对比**：第一版把「淘宝每周 ¥558」识别成了订阅 —— **周期性消费 ≠ 订阅**

【讲稿】这条最能说明「指标好看」和「做得对」是两件事。放宽阈值能识别出更多订阅，但全是误报。

## P13 S6 跨场景：状态机不由模型编排

```
记忆 → 日历 → 锁资(P2) → 下单 → 通知 → 回执
```

**三个标注**：
- 顺序写死在代码里，模型只负责认出「用户要做这件事」
- 每个写节点自带反操作 → 逆序回滚即完整撤销
- 到点主动提醒**只发建议卡，绝不静默下单**

【讲稿】为什么不让模型编排？会出「先下单后付钱」这种空转，撤销时也不知道该退什么。可逆性必须是结构性的。

## P14 上下文与自主性（技术深度页）

**上**：上下文三层

```
会话槽位   给妈妈转 → 追问金额 → 用户只回「100」即可继续
对象栈     买它 / 取消它 → 落到具体对象；无上下文时不猜
长期记忆   7 类白名单 + 类型校验；未存项明确承认，不编造
```

**下**：为什么不把对话历史整个塞进 prompt

> token 膨胀是小事。真正的问题是历史里的攻击文本会成为**新的注入面**，而且不可审计。
> 该存「他说要转 100 给妈妈」，不是存「他说的那句话」。

【讲稿】这一页是给技术评委的。我们没用 RAG，因为银行业务的答案是数据库里的数字，不是文档段落。

## P16 诚实的部分：已知限制

**这页不要跳过。** 评委最反感的是「全都完美」。

| 限制 | 原因 |
|---|---|
| 支付密码忘记无自助找回 | 演示环境靠 reset，正式需人工核验 |
| 限速与锁在进程内 | 单实例演示足够，多实例需 Redis |
| 会话历史不落库 | 刷新后只有草稿恢复，不是完整续接 |
| A6 生日惊喜偏演示性 | 真实需求存疑，做它是为了题眼 |
| 无障碍与适老化未做 | M1–M5 都假设用户能读卡片、能打字 |

【讲稿】说限制的时候要给出「为什么这么取舍」，而不是「没来得及做」。前者是工程判断，后者是欠债。

## 附：Q&A 预演（评委最可能问的 6 个问题）

| 问题 | 答题要点 |
|---|---|
| **你们和普通网银加个聊天框有什么区别？** | 普通网银是「页面 + 搜索」，我们是「意图 → 能力调用 → 结果」。判别标准：用户是否需要知道功能在哪个页面。 |
| **模型说错话怎么办？** | 模型没有执行权。它只能产出意图提议，过网关校验，最后必须用户双因子确认。参数被改了 HMAC 会拒。 |
| **为什么不做语音？** | 语音是输入通道，不改变安全模型。做了不加分，不如把 70 条攻击用例做扎实。 |
| **P3 不给智能体做，是不是能力不足？** | 是产品结论。解绑卡交给可能被注入的链路，等于把最高危权限外包。我们做的是「解释 + 深链 + 返回续接」，不是拒绝。 |
| **订阅识别会不会误报？** | 会，所以规则很硬：同商户 + 金额 ±1% + 同周期间隔，且排除电商外卖。第一版把「淘宝每周 ¥558」识别成订阅，就是放宽阈值的后果。 |
| **这个系统能上生产吗？** | 不能，我们没说能。单文件存储、进程内限速、会话不落库都不适合多实例。但**安全架构是可移植的**——P0–P3、HMAC 指纹、审计链、数据隔离，这四件换任何存储都成立。 |
