# 智能体银行 V2 修改方案（评审稿）

> 版本：V2 Draft v0.1 ｜ 日期：2026-10-12 ｜ 状态：待审核
>
> 核心定位转变：**V1 是"带 Agent 的银行 Demo"，V2 要做成"以安全为核心竞争力的 Agent 银行体系"**——安全问题是我们拿奖的差异化亮点，比赛规定功能是及格线，两者都要做，且安全要贯穿所有功能。

---

## 一、总体思路

| 维度 | V1 现状            | V2 目标                              |
| -- | ---------------- | ---------------------------------- |
| 安全 | 基本缺失，无验证流程、无权限控制 | 统一安全体系：认证、授权、验证、审计四位一体（**评审核心亮点**） |
| 账户 | 无登录注册            | 完整注册/登录/会话管理，敏感操作二次验证              |
| 转账 | 仅基础转账            | 普通 + 定时 + AA 转账，全部走安全验证链路          |
| 账单 | 可看月度账单但不清晰，无上传   | 账单上传解析 + 月度账单可视化重构                 |
| 理财 | 无                | 推荐、对比、风险评估、一键申购/赎回                 |
| 卡片 | 无                | 卡片管理（增删、默认、冻结、额度）                  |
| 联动 | 场景割裂             | 跨场景闭环：账单→分析→理财→执行                  |
| 界面 | 侧边按钮体验差          | 导航重构 + 整体视觉统一                      |

**一条主线贯穿**：所有新功能（转账、理财、卡片）都不是孤立堆上去的，而是作为 Agent 安全调用链路的演示场景——评委看到的每一个功能，背后都在跑"权限校验 → 风险评估 → 人工确认 → 审计留痕"的安全流程。**功能是安全体系的载体，安全是功能的灵魂。**

---

## 二、安全体系设计（核心拿奖点）

针对问题 1「安全问题、验证流程、权限问题」，建立四层安全架构：

### 2.1 第一层：身份认证（Authentication）

**登录注册流程**

- 手机号/邮箱 + 密码注册，登录支持验证码
- 会话管理：JWT（短期 access token + refresh token），支持登出与 token 吊销
- 支付密码独立于登录密码（理财申购/赎回、转账需验证）

**分层认证策略**

- L1 查询类操作（看余额、看账单）：登录态即可
- L2 写操作（添加卡、定时转账设置）：支付密码
- L3 资金操作（转账执行、理财申购）：支付密码 + 短信/邮箱验证码（演示环境可用模拟验证码）

### 2.2 第二层：Agent 权限体系（最重要的差异化亮点）

**Agent 权限分级（Permission Levels）**

| 级别     | 权限范围    | 典型操作               | 约束                  |
| ------ | ------- | ------------------ | ------------------- |
| P0 只读  | 查询类 API | 余额、账单、持仓查询         | 无需确认，自动脱敏           |
| P1 低敏写 | 非资金类写操作 | 设置定时转账、发起 AA 收款    | 一次性用户确认             |
| P2 资金类 | 资金变动操作  | 转账执行、理财申购/赎回       | 强验证（支付密码+验证码）+ 确认卡片 |
| P3 禁止区 | 高危操作    | 修改支付密码、解绑手机、关闭安全策略 | Agent 无权限，仅用户本人可操作  |

**权限网关（Policy Gateway）**

- Agent 的所有工具调用不直连银行 API，统一经过权限网关
- 网关校验：当前用户 → 该 Agent 会话 → 请求的 API → 命中权限级别 → 决定放行/要求确认/拒绝
- 动态限额：单笔/单日限额随权限级别递减，超额自动升级验证强度

**敏感数据脱敏**

- Agent 上下文中卡号、身份证、手机号自动脱敏（`6222****1234`）
- Agent 回复用户时经过输出过滤器，禁止回显完整敏感信息

### 2.3 第三层：验证流程（Human-in-the-Loop）

**Agent 发起 → 用户确认 → 执行**的标准链路：

```
用户指令 → Agent 理解并生成操作意图（结构化）
        → 权限网关评估 → 需要几级验证？
        → App 弹出确认卡片（操作摘要：金额/对象/时间，明文展示）
        → 用户验证（密码/验证码/指纹）
        → 执行 → 结果反馈 + 审计记录
```

- 确认卡片展示**操作摘要而非 Agent 的话术**，防止提示词注入诱导用户误确认
- 大额转账设置**延迟执行 + 可撤销窗口**（如 2 分钟冷静期）
- 风险引擎：异地、异常金额、异常频率 → 触发增强验证或直接拦截

### 2.4 第四层：审计与可追溯（Audit Trail）

- 全链路日志：用户指令 → Agent 思考/工具调用 → 网关决策 → 用户确认 → 执行结果，全部落库
- 提供可视化"安全日志"页面（本身也是演示亮点：评委能直观看到 Agent 每一步被权限体系管着）
- 支持操作回放与异常告警列表

### 2.5 反提示词注入（Prompt Injection 防护）

- 用户输入与系统指令严格隔离（结构化传递，不拼接进 system prompt）
- 账单上传等外部文本内容标记为不可信数据，Agent 不得将其中的"指令"当作命令执行
- 工具调用结果同样隔离，防止间接注入

> 💡 演示策略：准备一个"攻击演示"环节——现场演示注入攻击被权限网关拦截，比讲十页 PPT 都有说服力。

## 三、功能补齐方案

### 3.1 登录注册（问题 2）

- 注册：手机号/邮箱 + 密码 + 验证码，注册后引导完成风险测评与支付密码设置
- 登录：密码登录 + 验证码登录；连续失败锁定；异地登录提醒
- 找回密码流程（演示可简化）

### 3.2 转账增强（问题 2）

**定时转账**

- 支持单次定时与周期性（每周/每月 X 日）
- 可查看、取消待执行的定时任务
- 到期执行时走 P2 验证链路（提前提醒确认）

**AA 转账**

- 发起人创建 AA 活动：总金额、参与人、均摊/自定义份额
- 参与人各自确认付款（各自走验证流程——这里正好演示"每个人只对自己的资金有权限"）
- 状态面板：已付/未付/催付；全部到账后结算完成

### 3.3 账单体系（问题 3）

**账单上传**

- 支持 CSV 账单文件导入；图片账单 OCR 识别（技术成本高可降级为 CSV + 手动补录）
- 上传后自动分类（餐饮/交通/购物…），可手动修正
- 上传的账单文本进入 Agent 上下文前**强制脱敏+隔离**（安全体系呼应点）

**月度账单重构**

- 顶部概览卡：总支出/总收入/结余 + 环比
- 分类占比环形图 + 分类明细列表（图标、金额、笔数、环比箭头）
- 时间趋势折线图（日/周/月切换）
- 异常消费自动标红（单笔超阈值提醒）

### 3.4 理财模块（问题 4）

- **风险评估问卷**：注册后引导填写（C1–C5 风险等级），与产品风险等级匹配（适当性管理，本身是金融合规加分项）
- **产品列表与筛选**：活期/定期/基金，展示七日年化、期限、风险等级
- **产品对比**：多选 2–3 个产品，收益、风险、期限、起购金额多维对比表
- **智能推荐**：Agent 基于风险等级 + 账单结余 + 持仓情况推荐，并**说明推荐理由**（可解释性）
- **一键申购/赎回**：走 P2 强验证链路；申购时风险匹配校验（C2 用户买 R4 产品 → 弹风险警示）
- 持仓页：盈亏展示、到期提醒

### 3.5 卡片管理（问题 5）

- 绑卡/解绑（解绑属 P3 高危，演示"Agent 不能做"的边界）
- 设置默认付款卡
- 冻结/解冻（一键冻结，安全场景亮点）
- 额度查看与临时调整
- 可选加分项：虚拟卡生成（用于演示"最小权限"——给 Agent 生成一张限额虚拟卡执行任务）

### 3.6 跨场景联动（问题 6）

设计 2–3 条完整闭环场景作为演示主线：

1. **结余理财闭环**：月度账单分析 → Agent 发现连续 3 个月结余 > 5000 → 推荐匹配风险等级的产品 → 用户确认申购（P2 验证）→ 持仓跟踪
2. **AA 记账闭环**：发起 AA 聚餐 → 各自付款 → 自动生成记账条目 → 归入月度账单分类
3. **定时资金规划闭环**：设定每月发薪日自动转 X 元至理财（定时转账 + 理财申购组合，全链路安全验证）

Agent 主动式服务：账单月报推送、理财到期提醒、异常消费提醒（体现 Agent 的"主动性"而非被动问答）

### 3.7 界面优化（问题 7）

**侧边按钮/导航重构**

- 侧边栏改为可折叠分组式导航：首页 / 账户（卡片、账单）/ 转账（普通、定时、AA）/ 理财（推荐、持仓）/ 安全中心（新页面）
- 图标 + 文字标签，当前项高亮；移动端底部 Tab 适配
- 高频操作（转账、问 Agent）固定入口

**新增"安全中心"页面（把安全做成看得见的功能）**

- Agent 权限总览（当前各权限级别开关）
- 验证方式管理（支付密码、生物识别开关）
- 安全日志（审计流水）
- 限额设置

**整体视觉**

- 统一设计 token：主色、字号、圆角、间距
- 关键流程页面统一确认卡片样式（操作摘要 → 验证 → 结果）

## 四、技术架构建议

```
┌─ 用户（App / Web 前端）
│    └─ 确认卡片 · 支付密码 · 验证码
├─ API 网关（认证鉴权 · 限流）
├─ Agent 服务
│    ├─ LLM 对话编排（意图识别 → 工具规划）
│    ├─ 工具层：查询/转账/理财/卡片 API 封装
│    └─ 注入防护：输入输出隔离与过滤
├─ 权限网关（Policy Engine）★核心新增
│    ├─ 权限级别判定（P0–P3）
│    ├─ 验证策略下发（HITL 确认要求）
│    └─ 动态限额与风险引擎
├─ 银行核心服务
│    ├─ 账户/认证服务（注册登录、JWT）
│    ├─ 转账服务（普通/定时/AA）
│    ├─ 账单服务（导入解析、统计）
│    ├─ 理财服务（产品、测评、申赎）
│    └─ 卡片服务
└─ 审计服务（全链路日志 · 告警 · 回放）
```

> 若 V1 已有技术栈（前端框架、后端语言、数据库），V2 在其上增量改造即可，权限网关可先以中间件/拦截器形式实现，不必过度架构化。**待确认 V1 技术栈后细化。**

## 五、优先级与排期

| 优先级    | 内容                          | 理由            |
| ------ | --------------------------- | ------------- |
| **P0** | 登录注册 + 认证体系 + 权限网关框架 + 审计日志 | 一切的地基，也是拿奖核心  |
| **P0** | 安全中心页面 + 攻击拦截演示场景           | 核心亮点的可视化呈现    |
| **P1** | 普通转账接验证链路、定时转账、AA 转账        | 比赛规定功能        |
| **P1** | 理财五件套（测评/推荐/对比/申购/赎回）       | 比赛规定功能，联动场景载体 |
| **P1** | 账单上传 + 月度账单重构               | 比赛规定功能        |
| **P2** | 卡片管理（含冻结）                   | 规定功能，实现成本较低   |
| **P2** | 跨场景闭环打磨、界面/侧边栏优化、虚拟卡        | 体验分与演示效果      |

建议节奏：**第一阶段（P0 安全底座）→ 第二阶段（P1 规定功能，全部走安全链路）→ 第三阶段（P2 打磨 + 演示脚本排练）**。每阶段结束做一次内部验收。

## 六、验收 Checklist（摘要）

- [ ] 未登录状态无法访问任何业务接口
- [ ] Agent 无法执行 P3 禁止操作（现场演示被拦截）
- [ ] 所有资金操作必经用户确认卡片 + 强验证，且审计日志有完整记录
- [ ] 注入攻击演示：账单文本中夹带恶意指令，Agent 不执行且日志告警
- [ ] 定时转账到期正确执行且可提前取消
- [ ] AA 转账各参与方独立验证、状态正确流转
- [ ] 风险等级不匹配的申购触发警示
- [ ] 月度账单含概览/分类/趋势/异常标记
- [ ] 侧边导航重构完成，含安全中心入口
